B1Swap in real NZ Lotto history — source confirmed, ready to build
Replace data/draws.json with real draws and set meta.synthetic to false, which drops the warning banner automatically. Still no app code changes — the schema is the contract.

Shape confirmed by recon. Each draw renders as: six main numbers ascending, then the bonus ball, then the Powerball, then four Strike numbers. Draw 2608 (Sat 01 Aug 2026) is 8 14 15 24 26 30 | 7 | 4 | 30 26 8 24. The Strike numbers are always a subset of the six main numbers, which gives the parser a free self-check — if Strike is not a subset, the parse is wrong.

Only the first three fields matter here. Fresh Draw needs the six main numbers and the Powerball. Bonus ball and Strike are dropped: the exclusion set is keyed on six-number combinations via canonical(), and nothing else enters it.

Route: /lotto/ and each /lotto/<month>-<year> page carry full draw data inline, so the fetch is ~470 monthly pages rather than ~2,600 per-draw ones. /lotto/archive is the index back through history.

D1Decided: real draw history comes from lottoresults.co.nz
Owner's pick, and the only NZ source found. Settled by a one-off recon workflow rather than by argument, because the dev container cannot reach the site at all.

What the recon established. The /tools/ pages are aggregate statistics — frequency, pairs, triplets, recency — and none of that can reconstruct which six numbers fell together, so none of it is usable. The real archive is elsewhere: /lotto/, monthly pages, and /lotto/archive, all carrying full per-draw data inline. robots.txt is User-agent: * with no Disallow — nothing is off limits.

The game's own parameters, from the source rather than from memory. The site states Lotto is "a 6 from 40 game" with the Powerball "drawn from a separate pot of ten balls", numbered 1–10, drawn Wednesdays and Saturdays. That independently confirms mainPool 40, mainCount 6, powerballPool 10 in the data contract — the exact assumption CLAUDE.md warns not to take from training data. It was right to be checked, and it holds.

Two false starts worth keeping. The site is http-only, so the first run assumed https and got TypeError: fetch failed on every request while still reporting success. And the first pass scored pages with a regex that called the Keno page a likely source of six-number combinations — Keno draws 20 numbers, so any six in a row match — while missing the real Lotto page. Scoring was replaced with printing the page text and reading it. Decided 3 Aug 2026.
